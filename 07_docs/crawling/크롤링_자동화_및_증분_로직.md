# 크롤링 자동화 및 증분 로직

## 개요

매월 전체 상품을 풀 크롤링하는 방식에서 **증분 크롤링**으로 전환하여, 신규 제품만 전체 크롤링하고 기존 제품은 리뷰만 업데이트한다. 또한 `config.yaml`에서 카테고리를 자유롭게 활성화/비활성화할 수 있다.

---

## 아키텍처

```
run_pipeline.py
  ├── config.yaml 로드 (모드, 카테고리, 이력 경로)
  ├── _parse_active_categories() → 카테고리 필터 생성
  ├── CrawlHistory 로드 (증분 모드)
  │     └── 첫 실행 시 reviews_core.csv에서 bootstrapping
  └── run_all() 호출
        ├── 카테고리 필터 적용 → 크롤링 대상 소분류 결정
        └── 제품별 분기
              ├── 이력에 없음 (신규) → 전체 크롤링
              └── 이력에 있음 (기존) → 리뷰만 (cutoff 이후)
```

## 1. 크롤링 모드

### 증분 모드 (기본)

```bash
python 05_src/04_pipeline/run_pipeline.py
```

- `config.yaml`의 `mode: "incremental"` (기본값)
- 이력 파일(`crawl_history.json`)을 참조하여 신규/기존 제품을 구분
- **신규 제품**: 제품 정보 + 리뷰 + 성분 전체 크롤링
- **기존 제품**: 마지막 리뷰 날짜(cutoff) 이후의 새 리뷰만 수집, 성분 크롤링 생략

### 풀 모드

```bash
# CLI 옵션으로 강제
python 05_src/04_pipeline/run_pipeline.py --full

# 또는 config.yaml에서 설정
# mode: "full"
```

- 이력을 무시하고 모든 제품을 전체 크롤링
- 기존 풀 크롤링과 동일한 동작

## 2. 증분 크롤링 상세 흐름

### 2.1 제품별 분기 로직

```
카테고리 페이지에서 product_code 목록 수집
    │
    ├── history.is_new_product(code) == True (신규)
    │     └── crawl_product_detail(crawl_reviews=True, crawl_ingredients=True)
    │           → products, reviews, ingredients 모두 수집
    │           → history.update_product(code, max_review_date)
    │
    └── history.is_new_product(code) == False (기존)
          └── cutoff = history.get_last_review_date(code)
          └── crawl_product_detail(crawl_ingredients=False, review_cutoff_date=cutoff)
                → 리뷰만 수집 (cutoff 이하 날짜에서 조기 종료)
                → history.update_product(code, max_review_date)
```

### 2.2 리뷰 cutoff 조기 종료

`_extract_reviews(driver, product_code, cutoff_date)`:

- 리뷰는 날짜 역순(최신 → 과거)으로 나열됨
- 각 리뷰의 날짜가 `cutoff_date` 이하이면 즉시 루프 종료
- 이후 페이지의 리뷰는 모두 cutoff 이전이므로 추가 페이지 요청 불필요

```python
# 예: cutoff_date = "2026-01-28"
# 리뷰 날짜: 2026-02-15, 2026-02-10, 2026-01-28 ← 여기서 종료
#            2026-01-28 이하이므로 이미 수집된 리뷰
```

### 2.3 날짜 정규화

크롤러와 CSV의 날짜 형식이 다르므로 내부적으로 통일:

| 소스 | 형식 | 예시 |
|------|------|------|
| 크롤러 (다이소몰) | `YYYY.MM.DD` | `2026.02.19` |
| CSV (reviews_core) | `YYYY-MM-DD` | `2026-02-19` |
| **내부 통일** | `YYYY-MM-DD` | `2026-02-19` |

## 3. 크롤링 이력 관리

### 3.1 CrawlHistory 클래스

`05_src/01_crawling/crawl_history.py`

| 메서드 | 설명 |
|--------|------|
| `__init__(history_path)` | JSON 로드 (없으면 빈 dict) |
| `is_new_product(product_code)` | 이력에 없으면 `True` |
| `get_last_review_date(product_code)` | 마지막 리뷰 날짜 반환 (없으면 `None`) |
| `update_product(product_code, review_date)` | 이력 갱신 (더 최신 날짜만 반영) |
| `save()` | 임시파일 → rename 패턴으로 안전 저장 |
| `from_existing_csv(history_path, reviews_csv_path)` | 첫 실행 bootstrapping |

### 3.2 이력 JSON 구조

```json
{
  "last_updated": "2026-02-19",
  "products": {
    "1056665": {
      "last_crawled": "2026-02-19",
      "last_review_date": "2026-02-15"
    },
    "1048275": {
      "last_crawled": "2026-02-19",
      "last_review_date": "2026-02-10"
    }
  }
}
```

- `last_crawled`: 해당 제품을 마지막으로 크롤링한 날짜
- `last_review_date`: 해당 제품의 가장 최신 리뷰 날짜 (다음 증분의 cutoff으로 사용)

### 3.3 안전 저장

`save()`는 임시파일 작성 후 `os.replace()`로 원자적 교체를 수행한다. 크롤링 중 비정상 종료되어도 이력 파일이 손상되지 않는다.

### 3.4 Bootstrapping (첫 실행)

이력 파일이 없는 상태에서 증분 모드를 실행하면:

1. `crawl_history.json` 없음 → `from_existing_csv()` 호출
2. `reviews_core.csv` 존재 시 → product_code별 `max(write_date)` 추출하여 이력 초기화
3. `reviews_core.csv`도 없으면 → 빈 이력 → 모든 제품이 신규 → 풀 크롤링과 동일

```
[첫 실행 시나리오]

crawl_history.json 존재? ──Yes──→ 그대로 로드
        │
       No
        │
reviews_core.csv 존재? ──Yes──→ bootstrapping (이력 초기화)
        │                         → 기존 제품은 리뷰만 업데이트
       No
        │
빈 이력 생성 → 모든 제품 신규 → 풀 크롤링
```

## 4. 카테고리 관리

### 4.1 config.yaml 설정

```yaml
crawling:
  active_categories:
    스킨케어:
      - all                # 중분류 전체 소분류 활성화
    메이크업:
      - 베이스메이크업     # 특정 소분류만 지정
      - 립메이크업
    # 네일용품:            # 키 자체를 제거하면 비활성화
    맨케어:
      - all
```

### 4.2 카테고리 필터 규칙

| 설정 | 동작 |
|------|------|
| `- all` | 해당 중분류의 모든 소분류 활성화 |
| `- 기초스킨케어` 등 개별 지정 | 해당 소분류만 크롤링 |
| 중분류 키 자체 없음 | 해당 중분류 전체 비활성화 |
| `active_categories` 자체 없음 | DAISO_BEAUTY_CATEGORIES 전체 크롤링 |

### 4.3 오타 검증

`_parse_active_categories()`는 `DAISO_BEAUTY_CATEGORIES`와 교차 검증하여 잘못된 중분류명이나 소분류명에 대해 경고를 출력한다.

```
[경고] config.yaml의 '스킨캐어'은 DAISO_BEAUTY_CATEGORIES에 없습니다. 무시합니다.
[경고] '스킨케어' > '토너에센스'는 유효한 소분류가 아닙니다. 무시합니다.
```

### 4.4 현재 카테고리 구조 (6개 중분류, 33개 소분류)

| 중분류 | 소분류 수 | 소분류 목록 |
|--------|-----------|-------------|
| 스킨케어 | 5 | 기초스킨케어, 립케어, 팩/마스크, 자외선차단제, 클렌징/필링 |
| 메이크업 | 6 | 베이스메이크업, 아이메이크업, 립메이크업, 치크/하이라이터, 퍼프브러시세척, 향수 |
| 네일용품 | 5 | 네일리무버, 네일아트도구, 네일패치/팁, 매니큐어, 네일케어용품 |
| 맨케어 | 5 | 남성향수, 남성메이크업, 클렌징/쉐이빙, 남성스킨케어, 남성용면도기 |
| 미용소품 | 6 | 미용가위, 거울, 미용소도구, 화장소품수납, 공병, 세안소품 |
| 헤어/바디 | 16 | 염색/펌, 빗/브러쉬, 가발, 헤어스타일링, ... |

## 5. CLI 사용법

```bash
# 증분 크롤링 (기본) → 변환 → 저장
python 05_src/04_pipeline/run_pipeline.py

# 강제 풀 크롤링
python 05_src/04_pipeline/run_pipeline.py --full

# 크롤링 건너뛰고 기존 CSV로 변환만
python 05_src/04_pipeline/run_pipeline.py --skip-crawl \
    --products data/products.csv \
    --reviews data/reviews.csv \
    --ingredients data/ingredients.csv

# BigQuery 업로드 포함
python 05_src/04_pipeline/run_pipeline.py --upload-bq

# 로컬 저장만
python 05_src/04_pipeline/run_pipeline.py --local-only
```

| 옵션 | 설명 |
|------|------|
| `--full` | 강제 풀 크롤링 (config의 mode 무시) |
| `--skip-crawl` | 크롤링 건너뛰기 |
| `--products`, `--reviews`, `--ingredients` | 기존 CSV 경로 지정 |
| `--upload-bq` | BigQuery 업로드 포함 |
| `--local-only` | 로컬 저장만 |
| `--final-dir` | 기존 final/ CSV 디렉토리 경로 |

## 6. 크롤링 통계

`run_all()` 완료 시 다음 통계가 로그에 출력된다:

```
통계: 신규=12, 업데이트=658, 스킵=3
```

| 항목 | 의미 |
|------|------|
| 신규 | 이력에 없던 제품 → 전체 크롤링 수행 |
| 업데이트 | 이력에 있던 제품 → 리뷰만 업데이트 |
| 스킵 | 중복 또는 리뷰 비활성 시 건너뛴 제품 |

## 7. 효율성 비교

| 항목 | 풀 크롤링 | 증분 크롤링 |
|------|-----------|-------------|
| 제품 정보 수집 | 전체 (~670개) | 신규만 (~10~30개/월) |
| 성분 OCR | 전체 | 신규만 |
| 리뷰 수집 | 전체 (~30만 개) | cutoff 이후만 (~1~3만 개/월) |
| 예상 소요 시간 | 8~12시간 | 1~3시간 |
| 다이소몰 부하 | 높음 | 낮음 |

## 8. 주의사항

1. **이력 파일 삭제 시**: `crawl_history.json`을 삭제하면 다음 실행에서 bootstrapping이 다시 수행된다. `reviews_core.csv`가 있으면 이력이 복원되고, 없으면 풀 크롤링이 된다.

2. **카테고리 변경 시**: `config.yaml`에서 비활성화한 카테고리의 기존 제품은 이력에서 삭제되지 않는다. 다시 활성화하면 증분 크롤링이 이어진다.

3. **리뷰 날짜 역순 전제**: 다이소몰 리뷰가 최신순으로 정렬된다는 전제 하에 cutoff 조기 종료가 동작한다. 정렬 방식이 변경되면 cutoff 로직을 재검토해야 한다.

4. **크롤링 중 비정상 종료**: `run_all()` 완료 시점에 `history.save()`가 호출된다. 중간에 종료되면 이력이 갱신되지 않으므로, 다음 실행에서 동일 제품을 다시 처리한다 (데이터 유실 없음, 중복 가능).
