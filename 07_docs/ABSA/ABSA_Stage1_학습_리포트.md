## 1. 한 줄 요약

GPT-4o가 라벨링한 17,132개 리뷰로 KcELECTRA 모델을 학습시킨 결과, **Aspect Detection F1 = 0.60**, **Mentioned Sentiment F1 = 0.45** (미분류 제외 기준). 사용감/성능, 배송/포장, 색상/발색은 양호하나, **디자인(0.17), CS/응대(0.18), 품질/퀄리티(0.29)** 는 학습 데이터 부족으로 약점.

## 2. Stage 1이란?

ABSA 모델 학습은 2단계로 나뉜다:

```
Stage 1: GPT-4o 자동 라벨 데이터(17,132개)로 기본 학습    ← 이 문서
Stage 2: 전문가 골든셋(884개)으로 파인튜닝               ← 다음 단계
```

Stage 1만으로도 "대체로 맞는" 모델을 얻을 수 있지만, 최종 서비스 품질을 위해 Stage 2에서 보정한다.

## 4. 학습 데이터

### 4.1 Wide CSV 구조

하나의 리뷰가 하나의 행이고, 11개 aspect에 대해 각각 label과 mask 컬럼이 있다:

```
| review_id | text            | label_사용감_성능 | mask_사용감_성능 | label_디자인 | mask_디자인 | ... |
|-----------|-----------------|-----------------|----------------|------------|-----------|-----|
| 1001      | "발림성 좋아요"   | 1 (positive)    | 1 (학습에 포함)  | 0 (none)   | 1         | ... |
| 1002      | "색은 이쁜데..."  | 0 (none)        | 1              | 3 (neg)    | 0 (제외)   | ... |
```

**라벨 매핑:**

| 숫자 | 의미     | 설명                                    |
| ---- | -------- | --------------------------------------- |
| 0    | none     | 이 리뷰에서 해당 aspect가 언급되지 않음 |
| 1    | positive | 긍정적으로 언급됨 ("발림성 좋아요")     |
| 2    | neutral  | 중립적으로 언급됨 ("보통이에요")        |
| 3    | negative | 부정적으로 언급됨 ("끈적거려요")        |

**mask의 역할:**

- `mask=1`: 이 셀의 라벨은 신뢰할 수 있으니 학습에 사용
- `mask=0`: 이 셀의 라벨이 불확실하니 loss 계산에서 제외

GPT-4o가 "잘 모르겠다"고 판단한 셀은 mask=0으로 표시하여, 모델이 불확실한 라벨을 학습하지 않도록 한다.

### 4.2 11개 Aspect 카테고리

| #  | 카테고리    | 예시                                 | 학습 데이터 내 비중        |
| -- | ----------- | ------------------------------------ | -------------------------- |
| 1  | 배송/포장   | "배송 빠르고 포장 꼼꼼"              | 중간                       |
| 2  | 품질/퀄리티 | "만듦새가 좋다", "불량이다"          | 낮음                       |
| 3  | 가격/가성비 | "이 가격에 이 퀄리티면 갓성비"       | 중간                       |
| 4  | 사용감/성능 | "발림성 좋고 지속력 있다"            | **최다** (뷰티 특성) |
| 5  | 용량/휴대   | "용량 넉넉하다", "파우치에 쏙"       | 중간                       |
| 6  | 디자인      | "패키지 예쁘다", "디자인 촌스럽다"   | 낮음                       |

| 11 | 미분류      | (어떤 aspect에도 안 걸릴 때)         | 특수                       |

## 5. 모델 구조

### 5.1 아키텍처 개요

```
  리뷰 텍스트: "발림성 좋고 가격도 착해요"
         ↓
  ┌──────────────────────────────────┐
  │  KcELECTRA Encoder (768차원)      │
  │  beomi/KcELECTRA-base            │
  │  한국어 ELECTRA 사전학습 모델         │
  └──────────┬───────────────────────┘
             │ [CLS] 토큰 표현 (768차원)
             │
     ┌───────┴────────┐
     ↓                ↓
  ┌────────────┐  ┌──────────────────┐
  │ Sentiment  │  │ Aspect-Sentiment │    ← 메인 태스크
  │ Head       │  │ Head             │
  │ 768 → 3    │  │ 768 → 44 → [11,4]│
  └────────────┘  └──────────────────┘
     ↓                ↓
  [B, 3]          [B, 11, 4]
  neg/neu/pos     aspect별 none/pos/neu/neg
  (보조 태스크)     (메인 태스크)
```

### 5.2 왜 Multi-Task인가?

모델은 두 가지를 동시에 학습한다:

1. **Sentiment Head (보조):** 리뷰 전체의 감성 (긍정/중립/부정)
2. **Aspect-Sentiment Head (메인):** 11개 aspect 각각의 감성 (none/긍정/중립/부정)

보조 태스크를 함께 학습하면, encoder가 "이 리뷰는 전반적으로 긍정"이라는 맥락을 더 잘 파악하게 되어 메인 태스크 성능이 올라간다.

## 6. 학습 설정

### 6.1 하이퍼파라미터

| 파라미터             | 값                   | 설명                                  |
| -------------------- | -------------------- | ------------------------------------- |
| `model_name`       | beomi/KcELECTRA-base | 한국어 ELECTRA 사전학습 모델          |
| `max_length`       | 128                  | 토큰 최대 길이 (리뷰 대부분 128 이내) |
| `batch_size`       | 32                   | 한 번에 처리하는 리뷰 수              |
| `num_epochs`       | 10                   | 전체 데이터를 10번 반복 학습          |
| `learning_rate`    | 2e-5                 | BERT 계열 기본값                      |
| `warmup_ratio`     | 0.1                  | 초반 10%는 lr을 천천히 올림           |
| `weight_decay`     | 0.01                 | 과적합 방지용 L2 정규화               |
| `dropout`          | 0.1                  | encoder 출력에 드롭아웃 적용          |
| `max_grad_norm`    | 1.0                  | 그래디언트 클리핑                     |
| `sentiment_weight` | 1.0                  | 보조 태스크 loss 가중치               |
| `aspect_weight`    | 1.0                  | 메인 태스크 loss 가중치               |

### 6.2 불균형 처리

리뷰 데이터의 특성상 대부분의 aspect가 `none` (언급 안 됨)이다. 예를 들어 CS/응대는 전체 리뷰의 7%에서만 언급된다. 이런 불균형을 처리하기 위해:

**Class Weight (역빈도 가중치):**

```
가중치 = 전체 샘플 수 / (클래스 수 × 해당 클래스 샘플 수)
```

- none이 많으면 → none 가중치 낮아짐
- positive/neutral/negative가 적으면 → 해당 가중치 높아짐
- 모델이 "전부 none으로 찍기"를 하면 손해가 되도록 유도

**Masked Loss:**

```python
# mask=0인 셀은 loss 계산에서 완전히 제외
per_cell_loss = CE(logits, labels, reduction='none')  # [B, 11]
masked_loss = (per_cell_loss * mask).sum() / mask.sum()
```

## 8. None-Threshold 튜닝

### 8.1 왜 필요한가?

모델의 원래 출력은 4개 클래스(none/pos/neu/neg)에 대한 확률이다:

```
사용감/성능: P(none)=0.40, P(pos)=0.35, P(neu)=0.15, P(neg)=0.10
```

기본 상황: argmax (threshold 없음)

argmax → 0.40이 최대 → none 선택 (이 리뷰는 사용감 언급 안 했다고 판단)

하지만 실제로는 "발림성 좋아요"라고 써있는 리뷰였다면? 오분류

threshold는 **"none으로 판정하는 기준선"**

```
  규칙: P(none) >= threshold → none
       P(none) <  threshold → non-none 중 argmax
```

```
threshold = 0.45일 때  
  P(none)=0.40 < 0.45(threshold)
  → none이 아니다! → non-none 중 최대를 찾자
  → P(positive)=0.35 > P(neutral)=0.15 > P(negative)=0.10
  → positive 선택!!
```

```
threshold = 0.10일 때
  P(none)=0.40 >= 0.10(threshold)
  → none 확정 (기준이 너무 낮아서 거의 다 none 통과)
```

  직관적으로

  ┌──────┬──────────────────┬────────────┐
   │ threshold 높이 │                               의미                             │             결과                         │
  ├──────┼──────────────────┼────────────┤
   │ 낮게 (0.1)         │ "none 확률 조금만 있어도 none으로 인정"    │ none 많아짐 → 놓침 증가      │
  ├──────┼──────────────────┼────────────┤
   │ 높게 (0.45)      │ "none이 확실해야만 none으로 인정"            │ 언급 많아짐 → 과다 검출 가능 │
  └──────┴──────────────────┴────────────┘

즉, aspect마다 "none이 맞다고 판단하는 기준"을 다르게 설정하여 Detection 성능을 최적화하는 것 입니다.

### 8.2 튜닝 방법

1. Val set에서 모든 리뷰에 대해 모델의 softmax 확률을 수집
2. Aspect별로 threshold를 0.10~0.95까지 0.05 간격으로 grid search
3. 4-class Macro F1이 최대가 되는 threshold를 선택

| ----------- | -------------- | ---------------------------------------------------- |

## 9. 골든셋 평가 결과

> Val/Test set은 GPT-4o 자동 라벨을 분할한 것이므로 자동 라벨의 "자기 채점"이다.
> **최종 의사결정 기준은 무조건 골든셋(전문가 라벨)이다.**

### 9.1 평가 지표 설명

이 리포트에서 사용하는 4가지 지표 입니다.

**(1) Aspect Detection F1 (none vs non-none)**

"이 리뷰에서 해당 aspect가 언급되었는가?"를 맞추는 능력.

- 모델 예측을 이진화: none(0) vs 언급됨(1,2,3)
- 정답과 비교하여 F1 계산
- **왜 중요한가?** 언급 여부를 못 맞추면 감성 분석은 무의미하다.

**(2) Mentioned Sentiment F1 (pos/neu/neg) — "언급된 셀만"**

"실제로 언급된 aspect의 감성을 맞추는가?"를 보는 지표.

- GT label > 0인 셀만 대상 (none인 셀은 제외)
- 모델이 none(0)으로 예측했으면 → "놓침"으로 페널티
- **이게 진짜 ABSA 품질을 보여주는 지표.** 실서비스에서 "이 리뷰에서 사용감이 긍정적으로 언급됨"이라고 표시할 때의 정확도.

**(3) Aspect별 F1 + Confusion Matrix**

각 aspect를 4-class(none/pos/neu/neg)로 분류하는 전체 성능. Confusion matrix를 보면 "어떻게 틀리는지" 패턴을 알 수 있다.

**(4) 예측 분포 Sanity Check**

모델이 실제 분포와 얼마나 비슷하게 예측하는가? 예를 들어 GT에서 사용감/성능이 57%에서 언급되는데, 모델이 79%로 예측하면 과다 예측이다.

## 10. 약점 분석 — 왜 틀리는가?

### 10.1 디자인 (F1=0.27, Detection=0.21)

**문제:** 모델이 "디자인" 언급이 없는데도 negative로 과다 예측한다.

```
Confusion Matrix:
             pred_none  pred_pos  pred_neu  pred_neg
GT_none        569        24         0       176   ← 176건이 false alarm!
GT_pos          40         4         0         5   ← 49건 중 4건만 맞춤
GT_neg          34         1         0        25
```

- GT에서 none=769건인데, 모델이 176건을 negative로 잘못 예측
- GT에서 positive=49건인데, 모델이 4건만 맞춤 (recall=8%)
- **원인:** "디자인"이라는 단어가 리뷰에 직접 나오지 않고, "예쁘다", "촌스럽다" 같은 간접 표현이 많아서 학습 신호가 약함

### 10.2 CS/응대 (F1=0.40, Sent.F1=0.18)

**문제:** 데이터 자체가 극소량이다.

```
Confusion Matrix:
             pred_none  pred_pos  pred_neu  pred_neg
GT_none        802         0         0        18
GT_pos           1         0         0         0   ← positive 단 1건
GT_neu           1         0         0         0   ← neutral 단 1건
GT_neg          26         0         0        36
```

- 골든셋 884건 중 CS/응대 언급은 64건 (7.2%)
- positive=1건, neutral=1건 → 사실상 "negative or nothing" 이진 분류
- **원인:** 다이소 뷰티 리뷰에서 CS/응대를 언급하는 경우가 극히 드물고, 언급할 때는 거의 불만(negative)

### 10.3 품질/퀄리티 (F1=0.35, Sent.F1=0.29)

**문제:** "품질"이라는 개념이 너무 포괄적이다.

```
Confusion Matrix:
             pred_none  pred_pos  pred_neu  pred_neg
GT_none        587        31         0       148   ← 148건 false alarm
GT_pos          23         8         0         3   ← 34건 중 8건만 맞춤
GT_neg          26         0         0        51
```

- "퀄리티", "품질", "만듦새", "제조", "불량" 등 다양한 표현
- 디자인과 마찬가지로 negative 과다 예측 경향

### 10.4 과다 예측 패턴 요약

분포 Sanity Check에서 드러난 과다 예측:

```
Aspect         GT 언급률  →  Pred 언급률   차이
───────────────────────────────────────────────
사용감/성능      57.0%   →    78.6%       +21.6pp  ← 심각
품질/퀄리티      13.3%   →    27.4%       +14.1pp  ← 심각
디자인           13.0%   →    26.7%       +13.7pp  ← 심각
가격/가성비      18.9%   →    31.3%       +12.4pp
재질/냄새        17.1%   →    25.3%        +8.2pp
색상/발색        23.4%   →    32.8%        +9.4pp
용량/휴대        16.2%   →    17.9%        +1.7pp  ← 양호
CS/응대           7.2%   →     6.1%        -1.1pp  ← 양호
재구매             6.0%   →     8.8%        +2.8pp  ← 양호
```

**공통 패턴:** 모델이 none을 negative로 잘못 예측하는 경향. Threshold를 높이면 Detection은 좋아지지만 Recall이 떨어지는 트레이드오프.

## 11. 미분류 문제

### 11.1 현상

```
미분류 Confusion Matrix:
             pred_none  pred_pos  pred_neu  pred_neg
GT_none         55         4       762         0    ← 821건 중 762건을 neutral로!
GT_pos           0         0         8         0
GT_neu           0         0        52         0
GT_neg           0         0         3         0
```

- GT에서 none=821건(92.9%)인데, 모델이 762건을 neutral로 예측
- **모델이 미분류를 "전부 neutral"로 쏟아내는 현상**
- 결과: Detection F1=0.14, 4-class F1=0.06

### 11.2 왜 이런 일이?

학습 데이터에서 미분류는 "다른 10개 aspect에 해당하지 않는 나머지"로 정의되었고, 라벨링 시 **미분류=neutral로 강제 설정**한 경우가 많았다. 모델은 이를 "미분류 → neutral" 패턴으로 학습하여, 거의 모든 리뷰에서 미분류=neutral을 출력하게 됨.

### 11.3 권장 해결 방향

> 미분류는 "모델이 맞추는 aspect"가 아니라 **후처리로 생성**하는 것이 맞다.

**방법:**

1. 모델에서 미분류 헤드 제거 (10개 aspect만 학습)
2. 추론 시: 10개 aspect가 전부 none이면 → 미분류=neutral로 자동 태깅

**장점:**

- 모델 용량/학습 신호를 진짜 필요한 10개 aspect에 집중
- 미분류의 trivial한 F1=1.0이 전체 지표를 왜곡하는 문제 해소
- 어차피 미분류는 비즈니스적으로 "분석할 게 없는 리뷰"이므로 후처리로 충분
