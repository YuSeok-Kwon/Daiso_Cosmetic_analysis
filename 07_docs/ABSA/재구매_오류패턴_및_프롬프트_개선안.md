## 현재 프롬프트 문제점

### 문제 1: 재구매 aspect 정의가 너무 넓음

```
현재: 9. 재구매: 재구매 의사, 추천 (쟁여둠, 정착, 또 살)
```

- "추천"을 포함시켜 타인 권유까지 재구매로 분류
- 부정적 예시(X 케이스)가 전혀 없음

### 문제 2: 과잉 추론 방지 지침 부재

현재 프롬프트의 재구매 지침 (라인 256-260):
```
4. 재구매 (다른 이슈와 함께 나올 때)
- 재구매 의사가 명확하면 반드시 재구매 Aspect 포함
  - O: "또 살거예요", "재구매할게요", "쟁여둠", "정착", "계속 쓸"
  - O: "전에 써보고 좋아서 재구매"
  - O: "계속 쓰던 제품"
```

- O (올바른 예시)만 있고, X (틀린 예시)가 없음
- "만족 = 재구매"로 추론하지 말라는 **명시적 제약**이 없음

### 문제 3: 조건부 재구매 규칙 없음

- "~하면 재구매", "써보고 재구매"는 neutral이어야 하는데 규칙 부재
- 키워드 매칭이 문맥보다 우선시되는 구조

### 문제 4: "다른 색상/종류" 예외 규칙 없음

- "다른 컬러로 살 것" = 이 제품은 불만족 → 재구매 X

## 프롬프트 개선안

### 변경 1: Aspect 정의 수정 (라인 298)

```diff
- 9. 재구매: 재구매 의사, 추천 (쟁여둠, 정착, 또 살)
+ 9. 재구매: **이 제품**의 재구매 의사/행동만 (쟁여둠, 정착, 또 살, N번째 구매, 재구매했어요)
+    ※ 타인에 대한 "추천"은 재구매가 아님 → 사용감/성능 또는 미분류
```

### 변경 2: 재구매 혼동 방지 규칙 전면 교체 (라인 256-260)

```
**4. 재구매 (가장 엄격한 기준 적용 — 명시적 표현만 추출)**

[재구매 O — 반드시 추출]
  - 명시적 재구매 키워드: "재구매", "재주문", "또 살", "또 삼", "더 살", "쟁여둠", "쟁여놓"
  - 반복 구매 사실: "N번째 구매", "두개째", "세통째", "몇개째", "다 떨어져서 구매"
  - 명시적 정착: "정착템", "정착했다", "앞으로 이것만"
  - 명시적 지속: "1년째 사용", "꾸준히 구매", "계속 쓰고 있다"

[재구매 X — 절대 추출 금지]
  - 현재 만족 표현: "좋아요", "맘에 들어요", "잘 쓰고 있어요", "최고에요" → 사용감/성능
  - 사용 의지/계획: "써봐야겠어요", "써야겠어요", "애용할것같아요" → 사용감/성능
  - 첫 구매/호기심: "사봤어요", "구매했어요", "바로 구매" → 미분류
  - 브랜드/다이소 칭찬: "다이소 없인 못살아", "항상 애용하는 다이소" → 가격/가성비
  - 추천/타인 권유: "추천합니다", "장바구니에 담으세요" → 사용감/성능 또는 미분류
  - 대용량/추가 구매: "대용량구매", "하나 더 사봤어요" (첫 구매 문맥) → 용량/휴대
  - 미사용 재구매 의사: "사용못해봤지만 재구매하려" → 미분류

[다른 색상/종류 구매 — 문맥 판단 필수]
  - "다른 컬러로 살 것", "다른 종류로 사보려구요" → 이 제품은 재구매 X (색상/발색 또는 사용감/성능)
  - "같은 제품 다른 색도 살 것" → 재구매 positive

[조건부 재구매 — sentiment = neutral]
  - "효과 있으면 재구매", "써보고 재구매", "뒤집어지지만 않으면" → 재구매 **neutral**
  - 조건(~하면, ~한다면)이 붙으면 무조건 neutral

[부정 맥락 키워드 — 문맥 우선]
  - "정착할랬는데 안 맞는듯" → "안 맞는듯"이 핵심 → 재구매 negative 또는 사용감/성능
  - "쟁여두어야 할꺼같음" + 전체 톤 부정적 → 재구매 추출 금지
  - 재구매 키워드가 있어도 **전후 문맥이 부정이면 키워드 무시**

[판단 기준 요약]
  재구매 = "이 제품을 다시 사겠다/사고 있다"는 **명시적 의사 또는 행동**
  만족 ≠ 재구매. "좋다"고 해서 "또 사겠다"는 아님.
  확신이 없으면 재구매 Aspect를 추출하지 말 것 → 다른 Aspect로 분류하거나 미분류.
```

## 메타데이터 오염 대응 (코드 수준)

프롬프트 개선과 별도로 Batch API 코드에서 조치가 필요하다.

### 원인

`batch_labeling.py`에서 JSONL 생성 시, 이전 리뷰의 응답(aspect 태그 등)이 다음 리뷰의 입력에 누출.

### 대응안

1. **각 요청을 독립적으로 구성**: Batch API의 각 line이 완전히 독립적인 system + user 메시지를 가지도록 보장
2. **입력 텍스트 전처리**: 리뷰 텍스트에 "재구매", "aspect" 등의 메타데이터가 섞여있으면 제거
3. **후처리 검증**: reason 필드가 리뷰 원문에 없는 aspect명으로 시작하면 해당 라벨 제거

```python
# 후처리 검증 예시
ASPECT_NAMES = ['배송/포장', '품질/퀄리티', '가격/가성비', '사용감/성능',
                '용량/휴대', '디자인', '재질/냄새', 'CS/응대', '재구매', '색상/발색', '미분류']

def validate_reason(reason: str, review_text: str) -> bool:
    """reason이 aspect명으로 시작하면 메타데이터 오염 의심"""
    for name in ASPECT_NAMES:
        if reason.strip().startswith(name):
            if name not in review_text:
                return False  # 오염 의심 → 해당 라벨 제거
    return True
```
