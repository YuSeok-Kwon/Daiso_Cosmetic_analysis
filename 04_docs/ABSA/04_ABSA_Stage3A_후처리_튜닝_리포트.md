## 3. 3가지 후처리 변경

### 3.1 Design Rule Override (디자인 aspect)

모델의 디자인 예측을 완전히 무시하고, **키워드 규칙**으로 대체한다.

```
입력: 리뷰 텍스트 + 모델의 8-aspect 예측
출력: 디자인 aspect만 규칙 기반으로 교체, 나머지 7개는 모델 예측 유지

규칙 (우선순위 순):
  Tier 1 (positive 키워드 매칭): → 디자인=positive
    예쁘, 이쁘, 귀엽, 귀여, 깔끔, 고급, 앙증, 세련

  Tier 2 (negative 키워드 매칭): → 디자인=negative
    촌스럽, 투박, 칙칙, 유치, 조잡, 싸구려, 못생

  Tier 3 (구조물+수식어 조합): → 조합 감성 판단
    (디자인|패키지|용기|뚜껑|케이스) + (좋|마음에 들|이쁘|예쁘|별로|아쉽|...)

  매칭 없음: → 디자인=none
```

**구현 위치:** `s7_evaluation.py` → `apply_design_rule_override()`
**설정:** `s1_config.py` → `DESIGN_RULE_CONFIG`

### 3.2 사용감/성능 None-Threshold 보정 (0.10 → 0.03)

Stage 2에서 사용감/성능의 threshold는 0.10이었다. 이것이 **+23pp 과다검출**의 주범.

```
변경: threshold[사용감/성능] = 0.10 → 0.03

효과:
  Stage 2: P(none) >= 0.10 → none 예측 → GT_none 112건 중 42건만 none → 70건 FP
  Stage 3A: P(none) >= 0.03 → none 예측 → none이 더 쉽게 예측됨 → FP 대폭 감소
```

**왜 "낮추면" 검출이 줄어드는가?** → 4장에서 상세 설명.

### 3.3 Polar Threshold 조정 (0.55 → 0.50)

```
변경: polar_threshold = 0.55 → 0.50

작동 방식 (3단계):
  Step 1: P(none) >= t_none    → none (미언급)
  Step 2: max(P(pos), P(neg)) < t_polar → neutral (확신 없음)
  Step 3: else → argmax(pos, neg)

의미: t_polar를 0.55→0.50으로 낮추면 neutral 복원 기준이 엄격해짐
  → 확신이 0.50만 넘으면 pos/neg로 판정 → 과잉 neutral 억제
```

## 4. Threshold 의미론 — 핵심 발견

Stage 3A 튜닝 과정에서 가장 중요한 발견은 **none-threshold의 의미가 직관과 반대**라는 점이다.

### 4.1 None-Threshold 작동 방식

```python
# s7_evaluation.py의 apply_none_thresholds() 핵심 로직:
if P(none) >= threshold:
    predict = none  (미언급)
else:
    predict = argmax(pos, neu, neg)  (언급됨)
```

### 4.2 직관 vs 실제

| 조작                                 | 직관적 예상                         | 실제 효과                                      |
| ------------------------------------ | ----------------------------------- | ---------------------------------------------- |
| threshold**상향** (0.10→0.30) | "기준이 높아지니 검출이 줄어들겠지" | P(none)이 기준 못 넘음 →**검출 증가**   |
| threshold**하향** (0.10→0.03) | "기준이 낮아지니 검출이 늘어나겠지" | P(none)이 쉽게 기준 넘음 →**검출 감소** |

### 4.3 실증 — 사용감/성능 Grid Search 결과 (Golden Dev)

```
threshold │ Pred 언급% │ GT 언급% │ ±pp    │ Precision │ 해석
──────────┼────────────┼──────────┼────────┼───────────┼──────
   0.01   │   42.2%    │  55.8%   │ -13.6  │  0.811    │ 과소 검출
   0.03   │   52.2%    │  55.8%   │  -3.6  │  0.773    │ ★ 최적
   0.05   │   67.5%    │  55.8%   │ +11.7  │  0.689    │ 소폭 과다
   0.10   │   80.2%    │  55.8%   │ +24.4  │  0.644    │ 심각 과다 ← Stage 2
   0.20   │   88.5%    │  55.8%   │ +32.7  │  0.597    │ 더 악화
   0.50   │   96.5%    │  55.8%   │ +40.7  │  0.547    │ 거의 전부 "언급됨"
```

**교훈:** threshold를 "높이면" 검출이 줄어든다는 직관은 틀렸다. None-threshold는 "P(none)이 이 값 이상이면 none으로 판정"이므로, **낮출수록 none 예측이 쉬워져** 검출이 줄어든다.

### 7.4 Trade-off 분석

**얻은 것:**

- Detection Precision +6.3pp → 목표 0.65 달성
- 사용감 과다검출 해소 (+23pp → -6.5pp)
- 디자인 Precision 3배 향상 (0.17 → 0.50)
- F0.5 (precision-weighted) +3.5pp

**잃은 것:**

- Detection Recall -8.2pp (0.70 → 0.62): 일부 실제 언급을 놓침
- Detection F1 -0.8pp: 미미한 하락
- Mentioned Sentiment F1 -5.6pp: neutral recall 하락 + 감성 정확도 소폭 하락
- Neutral Recall -8.6pp: polar threshold 하향으로 neutral 복원 감소

**판단:** 30만 건 분석에서 **카운트 정확도(Precision)**가 **민감도(Recall)**보다 중요하다. Recall 하락은 "언급된 것 일부를 놓침"이고, Precision 하락은 "실제로 없는 것을 있다고 세어 분석 왜곡"이다. 비즈니스 의사결정에서 후자가 더 위험하므로, 이 trade-off는 합리적이다.

### 9.2 30만 건 추론 시 주의사항

```
1. Precision 0.67 = "언급됐다고 판단한 것 중 33%는 오탐"
   → 절대 카운트보다는 상대 비율(aspect 간 비교)로 해석할 것

2. 사용감/성능 -6.5pp = 약간의 과소 검출
   → 실제보다 5~7% 적게 집계될 수 있음

3. 디자인은 규칙 기반 = Recall 한계
   → "예쁘다" 패턴만 잡음. "디자인이 마음에 들어" 같은 복합 표현은 놓칠 수 있음

4. 색상/발색 +4.9pp = 소폭 과다 검출
   → 색상 관련 언급이 실제보다 약간 많게 집계
```
