# 대시보드 스코어 모델 재설계 리포트

**목적**: 데이터 누수·다중공선성 제거 + 연착륙 DNA 변수 기반 Logistic/OLS 모델 재설계

---

## 1. 재설계 배경

### 1.1 기존 모델의 문제점

| # | 문제                               | 설명                                                                                                                                                                 | 심각도 |
| - | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 1 | **데이터 누수**              | likes, shares, review_count, engagement_score는 연착륙의**결과**이지 **원인**이 아님. 이들을 독립변수로 사용하면 "미래를 알고 과거를 예측"하는 것과 같음 | 치명적 |
| 2 | **다중공선성**               | `engagement_score = 0.15×likes + 0.30×shares + 0.55×review_count`로 정의된 파생변수를 원본 변수와 함께 투입                                                     | 높음   |
| 3 | **프로젝트 정합성**          | category_2, brand가 독립변수에 없음 → 카테고리·브랜드 효과 미반영                                                                                                  | 중간   |
| 4 | **evaluate_new_brand**       | 실제 모델 `predict()`를 사용하지 않고 카테고리 평균을 매핑하는 방식                                                                                                | 중간   |
| 5 | **grade 함수 버그**          | 함수명 `grade_structure`로 정의 → 호출 시 `grade()`로 호출 (NameError)                                                                                          | 낮음   |
| 6 | **brand_summary_valid 순서** | 정의(Cell 30) 전에 사용(Cell 29)됨                                                                                                                                   | 낮음   |

### 1.2 기존 모델 Pseudo R² = 0.5147의 함정

기존 안정형 모델의 높은 Pseudo R²는 **누수 변수**(likes, shares, review_count 등)가 만들어낸 허상:

```
기존 독립변수 (누수 포함):
  np.log1p(likes)            p=0.556  ← 유의하지 않으면서 누수
  np.log1p(shares)           p=0.000
  np.log1p(review_count)     p=0.059
  np.log1p(engagement_score) p=0.645  ← engagement_score ≈ 위 3개의 선형결합
  cp_index                   p=0.722  ← 유의하지 않으면서 누수
  review_density             p=0.010  ← 누수 (결과 변수)
  age_days                   p=0.000
  is_functional              p=0.258
  log_price                  p=0.959
```

9개 중 유의한 변수 3개(shares, review_density, age_days) 모두가 **결과 변수**. 모델이 "오래된 인기 제품 = 연착륙"이라는 동어반복을 학습한 것.

## 2. 재설계 방향: 연착륙 DNA 변수

### 2.1 설계 원칙

> **"연착륙의 원인이 될 수 있는 제품 속성만 독립변수로 사용한다"**

SLI 분석에서 발견된 연착륙 DNA 6축 중 **제품 고유 속성**에 해당하는 변수만 선별:

| DNA 축   | 발견 사항                                 | 모델 변수                              |
| -------- | ----------------------------------------- | -------------------------------------- |
| 카테고리 | 립케어·팩/마스크·클렌징 유리, 색조 불리 | `C(category_2)`                      |
| 브랜드   | 브랜드 파워가 연착륙에 영향               | `brand_target_enc`                   |
| 성분     | 순한 식물 추출물, 심플 포뮬라(25개 이하)  | `ingredient_count`, `gentle_score` |
| 성분     | 수분 베이스 비율 높음                     | `water_base_ratio`                   |
| 가격대   | 1K~2K 초저가 연착륙 비율 38~56%          | `log_price`                          |
| 기능성   | 기능성 인증 제품의 신뢰도                 | `is_functional`                      |

### 2.2 변수 정의

#### 기존 유지 변수

| 변수              | 정의                                                | 비고      |
| ----------------- | --------------------------------------------------- | --------- |
| `is_functional` | 미백·주름개선·자외선차단·여드름 중 1개 이상 인증 | 0/1       |
| `log_price`     | `np.log1p(price)`                                 | 로그 변환 |

#### 신규 DNA 변수

| 변수                 | 정의                                     | 데이터 소스                         |
| -------------------- | ---------------------------------------- | ----------------------------------- |
| `C(category_2)`    | 2차 카테고리 더미 변수                   | `products_category`               |
| `brand_target_enc` | 브랜드별 연착륙 비율 (Smoothing=10 적용) | `sli_results` × `brands`       |
| `ingredient_count` | 제품당 총 성분 수                        | `products_ingredients`            |
| `water_base_ratio` | (Water + Polyol 성분 수) / 총 성분 수    | `ingredients_dic.ingredient_type` |
| `gentle_score`     | 1 − (알러지 유발 성분 수 / 총 성분 수)  | `ingredients_dic.is_allergic`     |

#### Target Encoding 수식

```
brand_target_enc = (n_brand × mean_brand + smoothing × global_mean) / (n_brand + smoothing)
```

- `n_brand`: 해당 브랜드의 상품 수
- `mean_brand`: 해당 브랜드의 연착륙 비율
- `smoothing = 10`: 소표본 브랜드의 과적합 방지
- `global_mean`: 전체 연착륙 비율

#### 제거된 변수 (누수)

| 제거 변수            | 제거 이유                                                         |
| -------------------- | ----------------------------------------------------------------- |
| `likes`            | 연착륙의 결과 (인기 → 좋아요)                                    |
| `shares`           | 연착륙의 결과                                                     |
| `review_count`     | 연착륙의 결과                                                     |
| `engagement_score` | 위 3개의 선형 결합 (다중공선성)                                   |
| `cp_index`         | engagement_score / price (누수 전파)                              |
| `review_density`   | review_count / 기간 (누수 전파)                                   |
| `age_days`         | 출시 후 경과일 → 안정형에서는 "오래된 제품이 유리"라는 편향 유발 |

## 3. 모델 구조

### 3.1 안정형 모델 (Logistic Regression)

```
목적: 신규 제품/브랜드의 연착륙 가능성 예측
종속: y = final_soft_landing (0/1)
독립: C(category_2) + brand_target_enc +
      ingredient_count + water_base_ratio + gentle_score +
      is_functional + log_price

데이터: df_model (final_soft_landing이 존재하는 ~706건)
```

**해석 방법:**

- 각 계수의 부호: 양(+)이면 연착륙 확률 증가
- `C(category_2)` 계수: 기준 카테고리 대비 각 카테고리의 연착륙 효과
- `brand_target_enc` 계수: 브랜드 연착륙 이력의 영향력
- Pseudo R²: 누수 제거 후 **낮아지는 것이 정상** (실제 예측력 반영)

**점수화:**

```python
stability_prob  = logit_model.predict(df_model)      # 연착륙 확률 (0~1)
stability_score = stability_prob.rank(pct=True) * 100  # 백분위 (0~100)
```

### 3.2 공격형 모델 (OLS Regression)

```
목적: 제품의 시장 반응 속도(리뷰 밀도) 예측
종속: np.log1p(review_density)    ← 기존: log(engagement_score)
독립: C(category_2) + brand_target_enc +
      ingredient_count + water_base_ratio + gentle_score +
      is_functional + log_price

데이터: df (전체 ~948건)
HC3 이분산 강건 표준오차 적용
```

**종속변수 변경 이유:**

- `engagement_score`는 likes/shares/review_count의 가중합 → 누수
- `review_density = review_count / (마지막리뷰일 − 첫리뷰일)` → 시간 정규화된 시장 반응 속도

**점수화:**

```python
growth_pred_log = ols_model.predict(df)               # log(review_density) 예측
growth_pred     = np.expm1(growth_pred_log)            # 원래 스케일
growth_score    = growth_pred_log.rank(pct=True) * 100  # 백분위 (0~100)
```

## 4. 데이터 파이프라인

### 4.1 데이터 소스 변경

```
bq_client.query_to_df()      ← BigQuery 7개 테이블 JOIN
```

### 4.2 BQ 쿼리 구조

```sql
-- 메인 쿼리: 제품 정보 통합
SELECT ps.product_code, ps.review_density, ...
       pc.category_1, pc.category_2,
       b.name AS brand, pcore.name AS product_name, pcore.price,
       f.is_whitening, f.is_wrinkle_reduction, f.is_sunscreen, f.is_acne,
       sr.final_soft_landing,
       rc_stats.first_review_date
FROM daiso.products_stats ps
  JOIN daiso.products_core pcore    ON ps.product_code = pcore.product_code
  JOIN daiso.products_category pc   ON ps.product_code = pc.product_code
  JOIN daiso.brands b               ON pcore.brand_id = b.brand_id
  LEFT JOIN daiso.functional f      ON ps.product_code = f.product_code
  LEFT JOIN daiso.sli_results sr    ON ps.product_code = sr.product_code
  LEFT JOIN (SELECT product_code, MIN(review_date) AS first_review_date
             FROM daiso.reviews_core GROUP BY product_code) rc_stats
    ON ps.product_code = rc_stats.product_code

-- 성분 쿼리: 성분 DNA 계산용
SELECT pi.product_code, pi.ingredient_id,
       d.ingredient_type, d.is_allergic, d.effect
FROM daiso.products_ingredients pi
  JOIN daiso.ingredients_dic d ON pi.ingredient_id = d.ingredient_id
```

## 5. evaluate_new_brand 재설계

### 5.1 기존 방식

```
1. 카테고리별 stability_score 평균을 매핑
2. is_functional 여부로 고정 보정값 가감
3. 실제 모델과 무관한 점수 생성
→ 모델이 학습한 패턴을 전혀 활용하지 못함
```

### 5.2 새 방식

```
1. 필수 피처 준비
   - log_price = np.log1p(price)
   - brand_target_enc = global_mean  (신규 브랜드 → 전체 평균)
   - ingredient_count/water_base_ratio/gentle_score
     → 입력값이 없으면 카테고리 평균으로 대체

2. 실제 모델 예측
   - stability_prob = logit_model.predict(tmp)
   - growth_pred_log = ols_model.predict(tmp)

3. 백분위 계산
   - 기존 제품 분포 대비 해당 SKU의 위치
   - 기존 브랜드 분포 대비 해당 브랜드의 위치

4. 등급 산출
   - grade(percentile) → A~E 등급
```

### 5.3 입력 예시

```python
new_brand = pd.DataFrame({
    "category_2": ["기초스킨케어", "자외선차단제", "기초스킨케어"],
    "is_functional": [1, 1, 1],
    "price": [5000, 3000, 5000],
    # 선택: ingredient_count, water_base_ratio, gentle_score
    #       미입력 시 해당 카테고리 평균으로 대체
})

result = evaluate_new_brand(new_brand)
```

### 6.3 예상 모델 성능 변화

| 지표                        | 기존 (누수 포함) | 재설계 후 (예상)    | 해석                                                     |
| --------------------------- | ---------------- | ------------------- | -------------------------------------------------------- |
| **안정형 Pseudo R²** | 0.5147           | **0.05~0.15** | 누수 제거로 크게 하락 —**정상**. 실제 예측력 반영 |
| **공격형 R²**        | 0.510            | **0.05~0.20** | 종속변수 변경(engagement→review_density) + 누수 제거    |
| **Condition Number**  | 1.2e+04          | **< 1,000**   | 다중공선성 해소로 대폭 개선 예상                         |

> **Pseudo R²가 낮아지는 것이 걱정될 수 있지만, 이것이 올바른 결과입니다.**
> 기존 0.51은 "인기 제품이 연착륙한다"는 동어반복을 학습한 결과이고,
> 재설계 후의 낮은 R²는 "제품 속성만으로 연착륙을 얼마나 설명할 수 있는가"의 순수한 측정값입니다.

## 7. 유의사항

1. **Pseudo R² 하락은 정상**: 누수 변수 제거의 자연스러운 결과
2. **신규 카테고리 입력 불가**: `evaluate_new_brand`에 학습 데이터에 없는 category_2를 입력하면 에러 발생 → 기존 카테고리 값만 사용
3. **성분 변수 미입력 시**: 해당 카테고리의 평균값으로 자동 대체 (evaluate_new_brand 내부 로직)

## 8. 변경 전후 비교 (Before / After)

### 안정형 모델 수식

```
[Before]
y ~ log(likes) + log(shares) + log(review_count) +
    log(engagement_score) + cp_index + review_density +
    age_days + is_functional + log_price

[After]
y ~ C(category_2) + brand_target_enc +
    ingredient_count + water_base_ratio + gentle_score +
    is_functional + log_price
```

### 공격형 모델 수식

```
[Before]
log(engagement_score) ~ cp_index + review_density +
                         age_days + is_functional + log_price

[After]
log(review_density) ~ C(category_2) + brand_target_enc +
                      ingredient_count + water_base_ratio + gentle_score +
                      is_functional + log_price
```

### 셀 구성 변경

```
[Before] 36셀 (CSV 기반, 누수 변수, 버그 포함)
[After]  30셀 (BQ 기반, DNA 변수, 버그 수정)

삭제 6셀: is_functional 분리셀, 탐색용 비교셀, price 분리셀,
         growth_target셀, 중복 brand_summary, 순서 오류 brand_summary_valid
```
