# 크롤링 자동화 및 증분 로직

## 개요

매월 전체 상품을 풀 크롤링하는 방식에서 **증분 크롤링**으로 전환하여, 신규 제품만 전체 크롤링하고 기존 제품은 리뷰만 업데이트한다. 크롤링 결과는 **BigQuery에 직접 UPSERT**되며, 로컬 CSV 저장은 비활성화되어 있다.

---

## 아키텍처

### 전체 파이프라인 (6단계)

```
run_monthly_pipeline.py (월간 오케스트레이션)
  │
  ├── Step 1: 증분 크롤링 → raw CSV [핵심, 실패 시 중단]
  ├── Step 2: 변환 + BQ UPSERT (19개 테이블) [핵심, 실패 시 중단]
  ├── Step 3: ABSA 증분 추론 → review_absa + review_aspects [실패 시 다음으로]
  ├── Step 4: SLI 연착륙 재계산 → sli_results [실패 시 다음으로]
  ├── Step 5: 검색트렌드 수집 → search_trends [실패 시 다음으로]
  └── Step 6: 대시보드 생성 [실패 시 로그만]
```

### 크롤링 + 변환 흐름 (Step 1~2)

```
run_pipeline.py
  ├── config.yaml 로드 (모드, 카테고리, 스토리지)
  ├── _parse_active_categories() → 카테고리 필터 생성
  ├── CrawlHistory 로드 (증분 모드)
  │     └── 부트스트래핑: BQ → 로컬 CSV → 빈 이력 순으로 폴백
  └── run_all() 호출
        ├── 카테고리 필터 적용 → 크롤링 대상 소분류 결정
        └── 제품별 분기
              ├── 이력에 없음 (신규) → 전체 크롤링
              └── 이력에 있음 (기존) → 리뷰만 (cutoff 이후)
                                        │
                                        ▼
                             transformer.py 변환
                               ├── BQ에서 기존 ID 매핑 로드
                               ├── ERD 19개 테이블 생성
                               └── etl_loader.py → BQ UPSERT
```

### 데이터 흐름

```
다이소몰 ──크롤링──→ raw CSV (임시) ──변환──→ BQ (19개 테이블, SSOT)
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                              노트북/분석          ABSA/SLI 파이프라인
                           (query_to_df)        (증분 추론/재계산)
```

## 3. 증분 크롤링 상세 흐름

### 3.1 제품별 분기 로직

```
카테고리 페이지에서 product_code 목록 수집
    │
    ├── history.is_new_product(code) == True (신규)
    │     └── crawl_product_detail(crawl_reviews=True, crawl_ingredients=True)
    │           → products, reviews, ingredients 모두 수집
    │           → history.update_product(code, max_review_date)
    │
    └── history.is_new_product(code) == False (기존)
          └── cutoff = history.get_last_review_date(code)
          └── crawl_product_detail(crawl_ingredients=False, review_cutoff_date=cutoff)
                → 리뷰만 수집 (cutoff 이하 날짜에서 조기 종료)
                → history.update_product(code, max_review_date)
```

### 3.2 리뷰 cutoff 조기 종료

`_extract_reviews(driver, product_code, cutoff_date)`:

- 리뷰는 날짜 역순(최신 → 과거)으로 나열됨
- 각 리뷰의 날짜가 `cutoff_date` 이하이면 즉시 루프 종료
- 이후 페이지의 리뷰는 모두 cutoff 이전이므로 추가 페이지 요청 불필요

```python
# 예: cutoff_date = "2026-01-28"
# 리뷰 날짜: 2026-02-15, 2026-02-10, 2026-01-28 ← 여기서 종료
#            2026-01-28 이하이므로 이미 수집된 리뷰
```

### 3.3 날짜 정규화

크롤러와 CSV의 날짜 형식이 다르므로 내부적으로 통일:

| 소스 | 형식 | 예시 |
|------|------|------|
| 크롤러 (다이소몰) | `YYYY.MM.DD` | `2026.02.19` |
| CSV / BQ | `YYYY-MM-DD` | `2026-02-19` |
| **내부 통일** | `YYYY-MM-DD` | `2026-02-19` |

## 4. 크롤링 이력 관리

### 4.1 CrawlHistory 클래스

`05_src/01_crawling/crawl_history.py`

| 메서드 | 설명 |
|--------|------|
| `__init__(history_path)` | JSON 로드 (없으면 빈 dict) |
| `is_new_product(product_code)` | 이력에 없으면 `True` |
| `get_last_review_date(product_code)` | 마지막 리뷰 날짜 반환 (없으면 `None`) |
| `update_product(product_code, review_date)` | 이력 갱신 (더 최신 날짜만 반영) |
| `save()` | 임시파일 → rename 패턴으로 안전 저장 |
| `from_existing_csv(history_path, reviews_csv_path)` | 로컬 CSV 부트스트래핑 (폴백용) |

### 4.2 이력 JSON 구조

```json
{
  "last_updated": "2026-02-19",
  "products": {
    "1056665": {
      "last_crawled": "2026-02-19",
      "last_review_date": "2026-02-15"
    },
    "1048275": {
      "last_crawled": "2026-02-19",
      "last_review_date": "2026-02-10"
    }
  }
}
```

- `last_crawled`: 해당 제품을 마지막으로 크롤링한 날짜
- `last_review_date`: 해당 제품의 가장 최신 리뷰 날짜 (다음 증분의 cutoff으로 사용)

### 4.3 안전 저장

`save()`는 임시파일 작성 후 `os.replace()`로 원자적 교체를 수행한다. 크롤링 중 비정상 종료되어도 이력 파일이 손상되지 않는다.

### 4.4 Bootstrapping (첫 실행)

이력 파일이 없는 상태에서 증분 모드를 실행하면 **BQ 우선, 로컬 CSV 폴백** 순으로 부트스트래핑한다.

```
[첫 실행 시나리오]

crawl_history.json 존재? ──Yes──→ 그대로 로드
        │
       No
        │
BQ reviews_core 조회 가능? ──Yes──→ BQ 부트스트래핑
        │                            (product_code별 MAX(review_date))
       No
        │
로컬 reviews_core.csv 존재? ──Yes──→ CSV 부트스트래핑 (폴백)
        │
       No
        │
빈 이력 생성 → 모든 제품 신규 → 풀 크롤링
```

**BQ 부트스트래핑 쿼리:**
```sql
SELECT CAST(product_code AS STRING) AS product_code,
       MAX(CAST(review_date AS STRING)) AS max_date
FROM `daiso.reviews_core`
GROUP BY product_code
```

## 5. 카테고리 관리

### 5.1 config.yaml 설정

```yaml
crawling:
  active_categories:
    스킨케어:
      - all                # 중분류 전체 소분류 활성화
    메이크업:
      - 베이스메이크업     # 특정 소분류만 지정
      - 립메이크업
    # 네일용품:            # 키 자체를 제거하면 비활성화
    맨케어:
      - all
```

### 5.2 카테고리 필터 규칙

| 설정 | 동작 |
|------|------|
| `- all` | 해당 중분류의 모든 소분류 활성화 |
| `- 기초스킨케어` 등 개별 지정 | 해당 소분류만 크롤링 |
| 중분류 키 자체 없음 | 해당 중분류 전체 비활성화 |
| `active_categories` 자체 없음 | DAISO_BEAUTY_CATEGORIES 전체 크롤링 |

### 5.3 오타 검증

`_parse_active_categories()`는 `DAISO_BEAUTY_CATEGORIES`와 교차 검증하여 잘못된 중분류명이나 소분류명에 대해 경고를 출력한다.

```
[경고] config.yaml의 '스킨캐어'은 DAISO_BEAUTY_CATEGORIES에 없습니다. 무시합니다.
[경고] '스킨케어' > '토너에센스'는 유효한 소분류가 아닙니다. 무시합니다.
```

### 5.4 현재 카테고리 구조 (6개 중분류, 33개 소분류)

| 중분류 | 소분류 수 | 소분류 목록 |
|--------|-----------|-------------|
| 스킨케어 | 5 | 기초스킨케어, 립케어, 팩/마스크, 자외선차단제, 클렌징/필링 |
| 메이크업 | 6 | 베이스메이크업, 아이메이크업, 립메이크업, 치크/하이라이터, 퍼프브러시세척, 향수 |
| 네일용품 | 5 | 네일리무버, 네일아트도구, 네일패치/팁, 매니큐어, 네일케어용품 |
| 맨케어 | 5 | 남성향수, 남성메이크업, 클렌징/쉐이빙, 남성스킨케어, 남성용면도기 |
| 미용소품 | 6 | 미용가위, 거울, 미용소도구, 화장소품수납, 공병, 세안소품 |
| 헤어/바디 | 16 | 염색/펌, 빗/브러쉬, 가발, 헤어스타일링, ... |

## 6. CLI 사용법

### 월간 전체 파이프라인 (권장)

```bash
# 전체 6단계 실행 (크롤링 → 변환 → BQ → ABSA → SLI → 검색트렌드)
python 05_src/04_pipeline/run_monthly_pipeline.py

# 크롤링+변환 건너뛰기 (ABSA/SLI/검색트렌드만)
python 05_src/04_pipeline/run_monthly_pipeline.py --skip-crawl

# 특정 단계만 실행 (예: ABSA + SLI만)
python 05_src/04_pipeline/run_monthly_pipeline.py --steps 3,4

# 실행 계획만 확인 (dry-run)
python 05_src/04_pipeline/run_monthly_pipeline.py --dry-run
```

| 옵션 | 설명 |
|------|------|
| `--skip-crawl` | 크롤링+변환 건너뛰기 (Step 3부터) |
| `--steps 3,4,5` | 특정 단계만 실행 (쉼표 구분) |
| `--dry-run` | 실행 안 하고 계획만 표시 |
| `--dataset daiso` | BigQuery 데이터셋 지정 |

### 크롤링+변환만 (Step 1~2)

```bash
# 증분 크롤링 → BQ UPSERT (기본)
python 05_src/04_pipeline/run_pipeline.py

# 강제 풀 크롤링
python 05_src/04_pipeline/run_pipeline.py --full

# 크롤링 건너뛰고 기존 CSV로 변환+BQ만
python 05_src/04_pipeline/run_pipeline.py --skip-crawl \
    --products data/products.csv \
    --reviews data/reviews.csv \
    --ingredients data/ingredients.csv
```

| 옵션 | 설명 |
|------|------|
| `--full` | 강제 풀 크롤링 (config의 mode 무시) |
| `--skip-crawl` | 크롤링 건너뛰기 |
| `--products`, `--reviews`, `--ingredients` | 기존 CSV 경로 지정 |
| `--upload-bq` | BigQuery 업로드 강제 (config 무시) |
| `--local-only` | 로컬 저장만 (BQ 비활성, 레거시) |

## 7. 파이프라인 실행 로그

`run_monthly_pipeline.py`는 각 단계의 결과를 **BQ `pipeline_log` 테이블**에 기록한다.

```sql
SELECT run_id, step_name, status, rows_affected, duration_sec
FROM `daiso.pipeline_log`
ORDER BY run_date DESC
```

| 컬럼 | 설명 |
|------|------|
| `run_id` | 파이프라인 실행 ID (자동 증가) |
| `step_name` | crawling, transform, absa, sli, search_trend, dashboard |
| `status` | success / fail |
| `rows_affected` | 처리된 행 수 |
| `duration_sec` | 소요 시간 (초) |
| `error_message` | 에러 메시지 (실패 시) |
| `meta` | 추가 메타데이터 (JSON) |

## 10. 주의사항

1. **이력 파일 삭제 시**: `crawl_history.json`을 삭제하면 다음 실행에서 부트스트래핑이 다시 수행된다. BQ에 데이터가 있으면 BQ에서 복원되고, 없으면 풀 크롤링이 된다.

2. **카테고리 변경 시**: `config.yaml`에서 비활성화한 카테고리의 기존 제품은 이력에서 삭제되지 않는다. 다시 활성화하면 증분 크롤링이 이어진다.

3. **리뷰 날짜 역순 전제**: 다이소몰 리뷰가 최신순으로 정렬된다는 전제 하에 cutoff 조기 종료가 동작한다. 정렬 방식이 변경되면 cutoff 로직을 재검토해야 한다.

4. **크롤링 중 비정상 종료**: `run_all()` 완료 시점에 `history.save()`가 호출된다. 중간에 종료되면 이력이 갱신되지 않으므로, 다음 실행에서 동일 제품을 다시 처리한다 (데이터 유실 없음, 중복 가능).

5. **BQ 연결 실패 시**: 부트스트래핑과 데이터 로드 모두 로컬 CSV 폴백이 있으므로, BQ 일시 장애 시에도 파이프라인이 동작한다. 단, UPSERT는 BQ가 필수이므로 변환 결과 적재는 실패한다.

6. **핵심/비핵심 단계 분리**: Step 1(크롤링)과 Step 2(변환)는 핵심 단계로, 실패 시 전체 파이프라인이 중단된다. Step 3~6은 실패해도 다음 단계로 계속 진행한다.
