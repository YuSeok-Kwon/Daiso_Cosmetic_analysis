## 1. 핵심 개념 가이드

분석에 사용된 주요 개념을 쉽게 풀어서 설명합니다.

### ① 시계열 분석 관련

**역월(Calendar Month) vs 상대월(Relative Month)**

| 구분             | 의미                                                    | 예시                  |
| ---------------- | ------------------------------------------------------- | --------------------- |
| **역월**   | 우리가 흔히 쓰는 '2024년 1월', '2월' 같은 절대적인 시간 | 2024-03, 2024-04, ... |
| **상대월** | 제품의 첫 리뷰가 발생한 시점을 '0개월'로 잡고 흐른 시간 | 0, 1, 2, 3, ...       |

> **왜 상대월을 썼나?**
> 제품마다 출시 시기가 다릅니다. 역월로 비교하면 2024년 3월 출시 제품과 2024년 9월 출시 제품의 "출시 초기 반응"을 같은 선상에서 비교할 수 없습니다. 모든 제품의 시계를 '0'으로 맞춰서 **생애 주기(Lifecycle)**를 공정하게 비교하기 위해 사용했습니다.

**DTW (Dynamic Time Warping)**

- 두 시계열의 **'모양'이 얼마나 비슷한지** 측정하는 알고리즘입니다.
- 일반적인 유클리드 거리는 같은 시점(1월↔1월, 2월↔2월)의 값만 1:1로 비교합니다. 하지만 DTW는 시간축을 유연하게 늘리거나 줄여서 **패턴의 유사성**을 찾습니다.

```
	일반 비교:  1월↔1월  2월↔2월  3월↔3월  (딱딱한 1:1 매칭)
	DTW 비교:   1월↔2월  2월↔3월  3월↔3월  (유연하게 최적 매칭)
```

> **왜 DTW를 썼나?**
> 어떤 제품은 1개월 차에 인기 정점을 찍고, 어떤 제품은 3개월 차에 정점을 찍을 수 있습니다. DTW는 이런 '시차'를 무시하고 **"결국 둘 다 초기에 떴다가 안정화되는 모양인가?"** 를 찾아내기에 적합합니다.

**TimeSeriesKMeans**

- 일반적인 KMeans 클러스터링은 점과 점 사이의 직선 거리를 계산하지만, TimeSeriesKMeans는 **DTW 거리**를 기반으로 비슷한 궤적을 가진 제품들을 그룹핑합니다. 즉, "인기가 올라가는 모양이 비슷한 제품끼리 같은 팀"으로 묶어주는 것입니다.

### ② 통계 및 생존분석 관련

**생존분석 (Survival Analysis)**

- 원래 의학에서 환자의 생존 기간을 분석하기 위해 개발된 통계 기법입니다. 우리 분석에서는 "환자" 대신 "제품", "사망" 대신 "인기 소멸"을 넣어서 **제품이 얼마나 오래 시장에서 사랑받는지**를 분석합니다.

**Kaplan-Meier (KM) 추정**

시간에 따른 '생존율'을 시각화하는 가장 대표적인 방법입니다.

- **가로축:** 출시 후 경과 개월 수
- **세로축:** 생존 확률 (1.0 = 100% 살아있음, 0.0 = 모두 사망)
- **읽는 법:** 그래프 선이 천천히 떨어질수록 오랫동안 사랑받고 있다는 뜻입니다.

**Cox Proportional Hazards (Cox PH) 모델**

- 단순히 생존 시간만 보는 게 아니라, **"어떤 요인이 생존 기간을 늘리거나 줄이는지"** 분석하는 회귀 모델입니다.

* **정의:** 특정 사건(상품의 시장 이탈 등)이 발생하기까지의 시간에 영향을 주는 여러 요인의 기여도를 분석하는 통계 모델입니다.
* **특징:** '판매 중'인 상태(절단 데이터)를 포함해 분석 가능하며, 각 변수(성분, 가격, 리뷰 감성 등)가 상품의 생존 위험을 몇 배나 증감시키는지 '위험비'로 산출합니다.

> **왜 Cox PH를 썼나?**
> "사용감 언급이 많으면 더 오래 살아남나?", "부정 비율이 높으면 빨리 사라지나?" 같은 인과관계를 **통계적으로 증명**하기 위해 사용했습니다.

**중도절단 (Censoring)**

- 생존분석에서 매우 중요한 개념입니다. 관측 기간이 끝났는데도 아직 "살아있는(인기 유지 중인)" 제품은 "사망하지 않았지만 언제 사망할지 모르는 상태"입니다. 이런 데이터를 그냥 빼버리면 정보 손실이 발생하므로, **"최소한 여기까지는 살아있었다"**는 정보를 활용하는 것이 중도절단 처리입니다.

### ③ 머신러닝 관련

**Pseudo Label (의사 라벨)**

- 정답(Label)이 없는 데이터에서, 통계적 규칙이나 클러스터링 결과로 **임시 정답**을 매기는 것입니다.

> **왜 Pseudo Label을 썼나?**
> "무엇이 연착륙이다"라는 명확한 정답 데이터가 없습니다. 그래서 DTW(형태), 생존분석(기간), 규칙(유지율) **3가지 방법이 공통으로 가리키는 제품**을 '연착륙'이라고 가정하고 ML 학습 데이터를 만들었습니다.

**SHAP (SHAPley Additive exPlanations)**

- 복잡한 머신러닝 모델(LightGBM 등)이 **왜 그런 예측을 했는지** 설명해 주는 도구입니다. 게임 이론의 Shapley Value에 기반하여, 각 피처(변수)가 결과에 기여한 정도를 수치화합니다.

> **왜 SHAP을 썼나?**
> 모델이 "이 제품은 연착륙입니다"라고 했을 때, "아, '후반부 유지율'이 높고 '기울기'가 안정적이어서 그렇구나"라고 **사람이 이해할 수 있는 근거**를 얻기 위함입니다.

## 2. 왜 이 다중 방법론을 사용했는가?

단순히 "리뷰가 많으면 좋은 제품"이라고 정의하면, 반짝 뜨고 사라지는 '바이럴' 상품을 걸러낼 수 없습니다.

### 다각도 검증 (Consensus)

| 방법론         | 무엇을 보는가                       | 단독 사용 시 한계 |
| -------------- | ----------------------------------- | ----------------- |
| DTW 클러스터링 | 시계열의**모양(패턴)**        | k 선택이 주관적   |
| 생존분석       | **얼마나 오래** 살아남는가    | 사망 정의에 민감  |
| 규칙 기반      | 3구간 유지율 + 기울기**수치** | 임계값이 주관적   |
| ML (LightGBM)  | **61개 피처**의 비선형 관계   | 라벨 품질에 의존  |

4가지를 모두 사용해서 **"진짜 실력이 있는 제품"**만 골라냅니다. 하나만 쓰면 발생할 수 있는 편향(Bias)을 최소화하고, **다수결로 신뢰도를 높이는** 전략입니다.

### 정성적 데이터의 정량화 (ABSA 통합)

- 단순 평점이 아니라 '사용감', '디자인', '가성비' 등 **구체적인 리뷰 내용을 수치화(ABSA)**하여 분석에 넣었기 때문에, 연착륙의 **이유**까지 분석이 가능합니다.

### 예측 모델로의 확장

- 과거 데이터를 분석하는 데 그치지 않고, 신제품이 나왔을 때 초기 데이터만 보고도 **"이 제품은 연착륙할 확률이 90%다"**라고 예측할 수 있는 모델(LightGBM)을 구축했습니다.

## 5. Step 1: 전처리 — 월별 시계열 구성

### 무엇을 하는가?

323,114건의 리뷰를 **"상품 × 월"** 단위로 요약합니다. 예를 들어 "VT 리들샷 300"이라는 제품이 출시 0개월 차에 리뷰 500건, 1개월 차에 420건, 2개월 차에 380건... 이런 식으로 시간 흐름에 따른 인기 추이를 만듭니다.

### 핵심 설계

```python
# 역월(Calendar Month) 기준 집계 — days // 30 보다 정확
reviews['review_month'] = reviews['review_date'].dt.to_period('M')

# 상품별 월별 리뷰 수 + 평균 평점 집계
monthly_reviews = reviews.groupby(['product_code', 'review_month']).agg(
    review_count=('review_date', 'size'),
    avg_rating=('rating', 'mean'),
)

# 상대월 계산: 첫 리뷰 월을 0으로 설정
ts_df['relative_month'] = (review_month - first_month).apply(lambda x: x.n)
```

### 품절 감지 로직

리뷰가 0건인 달이 연속 2개월 이상이면 **"품절 상태"**로 판단합니다. 품절된 제품은 인기가 없어서 리뷰가 없는 게 아니라, 물건 자체가 없는 것이므로 "사망" 판정에서 제외해야 공정합니다.

```
예시: [150, 120, 0, 0, 0, 80, 60]
                    ↑↑↑
               품절 구간으로 마킹
            → 사망 판정에서 제외
```

## 6. Step 2: DTW 시계열 클러스터링

### 목표

706개 상품의 인기 궤적을 **"모양이 비슷한 그룹"**끼리 자동으로 분류합니다.

### 구현 과정

**1단계: 시계열 행렬 구성**

706개 상품 × 12개월의 행렬을 만들고, 상품별로 **Min-Max 정규화**(0~1 범위)를 적용합니다.

```python
# 상품 × 월 피벗 테이블
pivot = ts_df.pivot_table(
    index='product_code', columns='relative_month',
    values='review_count', fill_value=0
)

# 상품별 Min-Max 정규화 → 리뷰 "양"이 아닌 "모양"만 비교
row_max = ts_matrix.max(axis=1, keepdims=True)
ts_normed = ts_matrix / row_max
```

> **왜 Min-Max 정규화?**
> 리뷰 9,504건인 VT 리들샷과 리뷰 50건인 소규모 제품을 같이 비교하려면, 절대적인 리뷰 "수"가 아니라 **"시간에 따라 올라가고 내려가는 모양"**만 봐야 합니다. 각 상품의 최대값을 1로 맞추면, 모든 제품을 0~1 사이의 "모양"으로 비교할 수 있습니다.

**2단계: 최적 클러스터 수(k) 탐색**

k=3부터 k=7까지 시도하며 **Silhouette Score** (군집 품질 지표, 1에 가까울수록 좋음)가 가장 높은 k를 선택합니다.

| k           | Silhouette Score        |
| ----------- | ----------------------- |
| **3** | **0.2943 (최적)** |
| 4           | 0.2899                  |
| 5           | 0.2597                  |
| 6           | 0.2376                  |
| 7           | 0.2137                  |

> Silhouette 점수가 k=3에서 0.29로 양호한 수준입니다. 보수적 필터링(25th percentile)으로 노이즈가 적은 상품만 남기면서 군집 분리도가 개선되었습니다. k=3이 가장 깔끔한 분리를 보여주므로 채택했습니다.

**3단계: 클러스터 자동 라벨링**

각 클러스터의 센트로이드(중심선)를 분석해서 자동으로 이름을 붙입니다.

```python
# 센트로이드를 3구간으로 나누어 특성 파악
early = centroid[:3].mean()    # Early (0~2개월)
mid   = centroid[3:6].mean()   # Mid   (3~5개월)
late  = centroid[6:].mean()    # Late  (6~11개월)

slope     = np.polyfit(range(len(c)), c, 1)[0]   # 전체 기울기
retention = late / max(early, 0.01)               # 후반부 유지율

# 분류 기준
if slope < -0.03 and retention < 0.3:
    → '급락형'        (빠르게 하락, 후반부 거의 없음)
elif slope < -0.01 and retention < 0.6:
    → '점진하락형'    (서서히 감소)
elif retention >= 0.6 and abs(slope) < 0.02:
    → '안정유지형'    (후반부까지 꾸준히 유지) → 연착륙
elif late > mid and slope > 0:
    → '후기상승형'    (갈수록 인기 상승) → 연착륙
```

## 7. Step 3: 생존분석

### 목표

"이 제품이 **얼마나 오래 살아남는가**"를 분석합니다.

### 사망 이벤트 정의

```
"피크 리뷰 수 대비 30% 이하로 2개월 연속 하회하면 사망"
```

구체적인 로직:

```python
peak = counts.max()                    # 해당 상품의 최대 리뷰 수
threshold = peak * 0.30                # 사망 기준선 = 피크의 30%

# 피크 이후의 월을 순서대로 확인
for m in range(peak_month + 1, ...):
    if stockouts[m]:                   # 품절 구간이면 건너뛰기
        consecutive_below = 0
        continue
    if counts[m] <= threshold:         # 기준선 이하면 카운트 증가
        consecutive_below += 1
        if consecutive_below >= 2:     # 2개월 연속이면 → 사망!
            death_month = m
            break
    else:
        consecutive_below = 0          # 기준선 회복하면 리셋
```

> **왜 이렇게 정의했나?**
>
> - 피크의 30%로 설정한 이유: 20%는 지나치게 관대하여 사실상 거의 사라진 상품만 "사망"으로 잡혔습니다. 30%로 상향하여 피크 대비 70% 이상 감소한 시점을 위험 신호로 포착합니다.
> - 연속 2개월을 요구하는 이유: 단 1개월 급락은 일시적 품절이나 프로모션 공백일 수 있으므로, 2개월 연속일 때만 진짜 "인기 소멸"로 판단합니다.

### Cox PH 모델: "무엇이 생존을 결정하는가?"

ABSA 감성 지표 + 상품 특성 **31개 공변량**을 넣어서, 어떤 요인이 생존에 영향을 주는지 분석했습니다.

| 지표                        | 값               | 해석                                    |
| --------------------------- | ---------------- | --------------------------------------- |
| **Concordance Index** | **0.7814** | 모델의 예측력 (1.0이 만점, 0.78은 우수) |
| 유의미한 공변량 (p < 0.05)  | **4개**    | 통계적으로 유의한 변수                  |

**유의미한 생존 영향 요인 (상위 극단값):**

| 공변량                       | exp(coef) = 위험비        | 해석                                       |
| ---------------------------- | ------------------------- | ------------------------------------------ |
| `mention_rate_디자인`      | **극단적 (수십만)** | 디자인 언급이 많을수록 사망 위험 극대화    |
| `mention_rate_용량/휴대`   | **극단적**          | 용량/휴대 언급이 많을수록 사망 위험 극대화 |
| `overall_neg_rate`         | **극단적**          | 부정 비율이 높을수록 사망 위험 극대화      |
| `mention_rate_사용감/성능` | 높음                      | 사용감 언급이 많을수록 사망 위험 상승      |

> **극단적 위험비의 해석:** `mention_rate_디자인`의 위험비가 수십만 배에 달하는 것은, 디자인에 대한 언급이 많은 제품일수록 외관에 대한 기대가 극도로 높고, 실망 시 빠르게 이탈하는 경향이 강하다는 것을 의미합니다. 다만 이러한 극단적 위험비는 해당 변수의 분산이 작거나 표본이 제한적일 때 발생할 수 있어, 방향성(위험 증가)에 초점을 맞추어 해석하는 것이 적절합니다.

![Cox PH 위험비 Forest Plot](../../02_outputs/figures/SLI/03_cox_hazard_ratios.png)

- **그래프 읽는 법:** 각 공변량의 위험비(Hazard Ratio)를 보여줍니다. HR 기준으로 **오른쪽으로 멀수록** 사망 위험을 높이는 요인입니다.
- **핵심 발견:** `mention_rate_디자인`이 HR ≈ 400,000~800,000으로 극단적인 위험비를 보입니다. `mention_rate_용량/휴대`와 `overall_neg_rate`도 매우 높은 위험비를 기록했습니다. 디자인·용량 언급이 많은 제품은 기대가 높은 만큼 실망 시 빠르게 이탈하는 경향이 있고, 부정 비율이 높은 제품은 당연히 사망 위험이 큽니다.
- **대부분의 ABSA 지표**(하단)는 HR ≈ 0 근처에 몰려 있어, 극단적 값을 가진 상위 3개 변수가 생존에 결정적 영향을 미칩니다.

**생존분석 기반 연착륙 상품: 363개 / 706개 (51.4%)**

> 기준: 생존시간이 상위 25% 이상(12개월 초과)이거나 관측 종료까지 생존(censored)한 상품

## 10. Step 6: ML 통합 모델 (LightGBM)

### Pseudo Label 생성: "3명의 심사위원이 만장일치로 동의해야 합격"

"연착륙"이라는 정답 데이터가 없으므로, 앞서 수행한 3가지 방법의 결과를 **투표**해서 임시 정답을 만듭니다. **만장일치(3/3)만 합격**으로 하여 가장 보수적인 기준을 적용합니다.

```python
# 3가지 방법의 결과를 합산
vote = dtw_label + survival_label + rule_label   # 각각 0 또는 1

# 만장일치(3개 모두 동의)만 → 연착륙(1), 아니면 → 비연착륙(0)
pseudo_label = 1 if vote >= 3 else 0
```

### 규칙 기반(Rule-based) 연착륙 기준

3가지 방법 중 "규칙 기반"은 다음 조건을 모두 만족해야 합니다:

```python
# 3구간 유지율 조건
retention_ok = (late/early >= RETENTION_LATE_RATIO) and
               (mid/early >= RETENTION_MID_RATIO)

# 기울기 조건
slope_ok = slope > SLOPE_MIN

# 둘 다 만족 → 규칙 기반 연착륙
is_soft_landing_rule = retention_ok and slope_ok
```

### LightGBM 5-Fold Stratified CV

61개 피처와 152개 Pseudo Label로 모델을 학습합니다.

**모델 설정:**

```python
params = {
    'objective': 'binary',           # 이진 분류
    'metric': 'binary_logloss',
    'learning_rate': 0.05,           # 학습률 (작을수록 안정적)
    'num_leaves': 31,                # 트리 복잡도
    'max_depth': 6,                  # 최대 깊이
    'min_child_samples': 10,         # 과적합 방지
    'subsample': 0.8,                # 행 샘플링 80%
    'colsample_bytree': 0.8,         # 열 샘플링 80%
    'is_unbalance': True,            # 클래스 불균형 자동 보정
    'n_estimators': 300,             # 최대 트리 수
    'early_stopping_rounds': 30,     # 30라운드 개선 없으면 중단
}
```

> **왜 5-Fold Stratified CV?**
> 데이터를 5등분해서, 매번 4개로 학습하고 나머지 1개로 검증합니다. 이렇게 5번 반복하면 **모든 데이터가 한 번씩 검증에 사용**되므로, 과적합 없이 공정한 성능 평가가 가능합니다. "Stratified"는 각 fold에서 연착륙/비연착륙 비율을 동일하게 유지한다는 뜻입니다.
